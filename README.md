# 드래프트 룸 — KBO 신인 드래프트 시뮬레이션

가상의 2027 KBO 신인 드래프트에서 한 구단을 맡아 5·8·11라운드 중 원하는 길이로 지명을 하고, 뽑은 선수들이 2027–2036 10시즌 동안 어떻게 자라고, 군대에 가고, 은퇴하는지 지켜보는 웹 게임입니다.

## 실행

`index.html` 파일 하나를 브라우저로 여세요. 서버·설치·인터넷 연결이 필요 없습니다. 모바일에서는 파일 미리보기 앱이 아니라 JavaScript가 도는 브라우저로 열어야 합니다.

`examples/demo-ten-seasons.json`을 게임의 ‘불러오기’로 열면 10시즌을 다 마친 진행 상태를 바로 볼 수 있습니다.

## 게임 한눈에

1. **구단 선택**: 10개 구단, 난이도(쉬움/보통/어려움), 지역 1차 지명 여부, 라운드 수(5/8/11).
2. **예상·추천**: 언론 두 곳의 1라운드 모의 지명과 스카우트 팀장의 추천 3명.
3. **드래프트**: 후보 400명(고졸 264, 대졸 56, 대학 얼리 24, 2년제 24, 독립 12, 해외파 6, 복귀 선수 13 등). 드물게 야구 유학파·MLB 경험자·기타 해외리그 복귀자가 나옵니다. 20–80 스카우팅 등급과 최고 구속, 대졸 의무 지명 1명(4년제·2년제 졸업예정자).
4. **계약 협상**: 구단 예산(약 12–15억 원) 안에서 지명 선수마다 계약금을 제시합니다. 선수는 받아들이거나, 다시 요구하거나, 거부하고 대학·해외로 떠납니다. 진학 희망·해외 구단 관심을 밝힌 선수는 요구액이 높고 거부하기 쉽습니다.
5. **육성선수 계약**: 남은 예산으로 미지명 선수 최대 5명(1명 3000만 원). 첫 시즌엔 1군 주전이 될 수 없습니다. 그러고도 남은 돈은 육성 지원금이 되어 첫 3시즌 성장 속도를 높입니다.
6. **입단**: 단장 기자회견(질문 세 개와 약속)과 입단 소감.
7. **10시즌**: 보직·기록·성장·부상·트레이드·방출·은퇴가 해마다 이어집니다.
   - **병역**: 2년 차부터 비시즌마다 우리 선수의 입대를 정합니다(구단 판단·상무 지원·현역 입대·미루기). 만 28세가 되는 해에는 입대해야 합니다. 상무는 퓨처스에서 뛰며 성장하고, 현역·사회복무요원은 기량이 조금 떨어집니다.
   - **국가대표**: 2028 LA 올림픽, 2030 도하·2034 리야드 아시안게임. 메달 조건을 채우면 병역 특례를 받습니다.
   - 기록실은 AVG/OBP/SLG/OPS와 WAR(게임 내 추정치)을 보여 주고, 스카우트의 FV(미래 가치)는 매 시즌 다시 매겨집니다. 팬심도 시즌마다 순위·주전 배출·국가대표 메달에 따라 움직입니다.
8. **평가**: 10개 구단의 드래프트를 WAR·주전 배출·기량 발전으로 비교합니다. 중간 평가는 언제든 볼 수 있습니다.

시스템이 어떻게 동작하는지는 [`docs/ANALYSIS.md`](docs/ANALYSIS.md)에 정리했습니다. 시작 화면의 ‘업데이트’ 상자에서 버전별 변경 내용(`CHANGELOG.md`)을 볼 수 있습니다.

## 저장

- 진행 상황은 브라우저 `localStorage`에 자동 저장됩니다.
- ‘진행 파일 저장’으로 JSON을 받을 수 있습니다.
- 저장에는 게임의 입력(설정·시드·내 지명·계약 제시액·재협상 결정·육성선수·기자회견 답·병역 결정·진행 시즌 수)만 들어갑니다. 10시즌 진행 파일도 1KB가 안 됩니다. 불러올 때 나머지를 다시 계산합니다.
- 저장에는 시뮬레이션 버전(`sim`)이 기록됩니다. 규칙이 바뀐 버전에서 이전 저장을 열면 다른 결과로 이어 가지 않고, 이어 할 수 없다고 알려 줍니다.
- 0.9.0은 계약 협상 규칙이 추가되어(`sim` 0.9) 0.8.x 이전 저장을 이어 할 수 없습니다. 이전 자동 저장은 지우지 않고 따로 보관합니다.

## 폴더 구조

```
index.html            빌드 결과물(이 파일 하나로 실행)
src/
  template.html       HTML 뼈대
  styles/main.css     스타일시트
  core/               게임 로직(브라우저·Node 공용, DOM 없음)
    clubs catalog names ko biography   정적 데이터와 한국어 조사
    grades prospects                   20–80 등급, 선수 풀 생성
    scouting draft-ai press            팀장·CPU·언론
    writer voices                      스카우트 노트·기사·댓글·인터뷰 문장(시뮬레이션과 분리된 난수)
    tuning                             밸런스 숫자(시즌·경력·평가) 모음
    season career engine               시즌·5년 경력·진행과 저장 복원
  ui/                 화면(순수 함수로 HTML 생성) + app.js(상태·이벤트)
tests/                단위·DOM·골든·브라우저·밸런스 테스트
docs/ANALYSIS.md      시스템·코드 분석
build.py              src → index.html
release.py            dist/에 배포용 HTML과 소스 zip 생성
```

`src/`를 고쳤다면 `python3 build.py`로 `index.html`을 다시 만드세요.

### 밸런스 조정

시즌·경력·평가의 숫자는 모두 `src/core/tuning.js`에 이름과 설명을 붙여 모아 두었습니다. 값을 바꾸면 결과가 바뀌므로 다음 순서를 따르세요.

1. `tuning.js` 수정
2. `src/core/engine.js`의 `SIM_VERSION` 올리기. 이전 버전 저장을 다른 결과로 이어 가지 않게 합니다.
3. `node tests/golden.cjs --write`로 기준 다시 기록
4. `npm run test:balance`로 통계 확인

## 개발

Node.js 22+ 와 Python 3가 필요합니다.

```bash
npm ci
npm run build          # src → index.html
npm test               # 단위·DOM 테스트 + 골든 마스터(시뮬레이션 결과 불변 확인)
npm run test:browser   # 실제 Chromium, 4개 화면 크기로 전체 진행(CHROMIUM_BIN으로 경로 지정)
npm run test:balance   # 600회 전 구단 밸런스 실험
npm run release        # dist/에 배포 파일
```

- **골든 마스터**(`tests/golden.cjs`): 선수 풀 3개와 5년 완주 게임 6개의 해시를 비교합니다.
  - 문구만 고쳤다면 `node tests/golden.cjs --write`로 기준을 다시 기록하면 됩니다.
  - 숫자나 지명이 바뀌었다면 시뮬레이션 동작이 바뀐 것입니다. 기존 저장이 다른 결과로 이어지지 않도록 `src/core/engine.js`의 `SIM_VERSION`을 먼저 올려야 `--write`가 허용됩니다.

## 범위와 주의

- 구단명을 뺀 선수·학교·해외 구단·기록·전력은 모두 게임용 가상 데이터입니다.
- 공식 KBO 규정이나 실제 선수 평가를 재현하지 않습니다.
- 지역 1차·의무 지명·해외 복귀 자격·포스트시즌은 단순화한 규칙입니다.
- 계약금 협상, 지명 거부, 연례 드래프트, 이도류, 수동 트레이드는 없습니다.
